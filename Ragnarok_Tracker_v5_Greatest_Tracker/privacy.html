Privacy & Security

This page explains what the tracker stores, what cloud sync sends to the server, how pairing codes work, and the security protections used by this unofficial fan-made project.

On your device

Local data

The tracker saves your characters, quest checks, run counters, duration estimates, optional quest guidance, Adventure Journal entries (including build needs, goals, Trade House targets, dream items, prices, notes, and progress), priorities, settings, history, and local restore snapshots in your browser so the app can work offline.

If cloud sync is connected, the browser also keeps the room ID and pairing secret needed for automatic synchronization. That credential is kept separately from tracker backups and is not included in exported tracker JSON.

Optional

Cloud sync

Cloud sync sends your tracker state, including Adventure Journal entries when you use them, to the tracker server, which stores it in Supabase together with a room ID, revision number, and update timestamp.

The server does not store the pairing secret itself. It stores a SHA-256 hash used to verify future sync requests.

Treat it like a password

Pairing-code safety

Anyone who obtains a valid pairing code can access that cloud room. Do not post it publicly, include it in screenshots, or send it to people you do not trust.

v5.2 lets you rotate the pairing code if it may have been exposed, or revoke the cloud pairing to invalidate it for every device.

Abuse prevention

Rate limiting

The sync API limits unusually high request volumes, repeated room creation, and failed authentication attempts. For this protection, the server may temporarily store cryptographic hashes derived from network addresses and request counters. The tracker rate-limit table does not store the raw address.

Hosting and database providers may maintain their own operational or security logs under their respective policies.

Payments

Support links

Support is optional. The tracker links to Buy Me a Coffee, which is a separate service. The tracker does not collect, process, or store your payment-card information.

Notifications & music

Browser features

Notification permission is managed by your browser or device. A custom music file you choose is used locally in the current browser session and is not uploaded through cloud sync.

v5.2 protections

Security controls

  • HTTPS with HSTS and additional browser security headers.
  • A Content Security Policy that restricts executable scripts and resource sources.
  • Clickjacking protection that prevents the tracker from being embedded in another site.
  • Server-side tracker-state validation and payload-size limits before cloud data is stored.
  • Generic cloud authentication errors so room existence is not disclosed.
  • Database-backed rate limits for sync traffic, room creation, credential rotation, revocation, and failed authentication.
  • Supabase Row Level Security with no public table policies; cloud database access is performed by the server.
Your controls

Disconnecting and deleting data

Disconnect this device removes the cloud credential from that browser but keeps its local tracker data. Revoke pairing everywhere deletes the cloud room and invalidates the pairing code for all devices while keeping the current device's local tracker data.

You can remove local tracker data by clearing site data for this website in your browser. Export a backup first if you want to keep a copy.

Important

No system is unhackable

These controls reduce common risks, but no website or cloud service can guarantee absolute security. Keep your devices and browsers updated, protect your accounts with multi-factor authentication, and keep your pairing code private.
